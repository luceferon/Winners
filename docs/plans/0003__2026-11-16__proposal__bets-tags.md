# Теги и категории для ставок

## Workflow State

- Status: Rejected
- Решение: отклонено 2026-11-16. Теги и категории ставок не входят в текущий
  объём работ; схема данных, API и интерфейс остаются без изменений.
- Цель (исторически): позволить пользователю группировать ставки по
  произвольным тегам (стратегия, лига, букмекерская линия, эмоциональное
  состояние и т.п.) и фильтровать/анализировать статистику по тегам.

## Мотивация

Сейчас ставки можно фильтровать только по виду спорта и источнику. Пользователь
не может выделить, например, «ставки по стратегии value», «ставки на топ-лиги»
или «ставки, сделанные на эмоциях». Теги решают эту проблему без изменения
схемы данных источников.

## Рассмотренные подходы

### Выбранный: отдельная таблица `tags` + связь `bet_tags`

- Таблица `tags` (`id`, `name` unique, `color` опционально, `created_at`).
- Таблица `bet_tags` (`bet_id`, `tag_id`) — many-to-many.
- Теги можно добавлять при создании/редактировании ставки; список тегов
  управляется в настройках (или создаётся «на лету» в форме ставки).
- В статистике добавляется фильтр по тегу и разбивка по тегам.

- Плюсы: гибко, несколько тегов на ставку, переиспользуемые теги.
- Минусы: две новые таблицы, изменения в схеме, формы и статистике.

### Отклонённый: одно текстовое поле `tags` (JSON/строка)

Хранить теги как JSON-массив в колонке `bets.tags`. Отклонён: сложно
фильтровать и агрегировать по тегам в SQL, нет нормализации названий.

### Отклонённый: подкатегории в виде спорта

Расширять виды спорта подкатегориями. Отклонён: смешивает доменные понятия
(вид спорта и пользовательская категория), негибко.

## Implementation Tasks

1. **Модели** — добавить `Tag` и ассоциативную таблицу `bet_tags`
   (many-to-many между `Bet` и `Tag`).
   - Files: `app/models.py`.
   - Verification: `init_db` создаёт таблицы, связь работает в ORM.

2. **API и сервисы** — CRUD тегов (`/api/tags`), добавление/удаление тегов
   у ставки (`POST /api/bets/{id}/tags`, `DELETE /api/bets/{id}/tags/{tag_id}`),
   теги в `Bet.as_dict()`.
   - Files: `app/api/tags.py` (новый), `app/services/bets_service.py`,
     `app/schemas.py`.
   - Verification: тесты на создание тега, привязку к ставке, фильтр по тегу.

3. **Фильтрация и статистика** — параметр `tag_id` в `GET /api/bets` и
   `GET /api/stats/summary`; в статистике — график/таблица «по тегам».
   - Files: `app/services/bets_service.py`, `app/services/statistics_service.py`.
   - Verification: тест на фильтрацию списка и сводки по тегу.

4. **UI** — поле тегов в форме ставки (autocomplete + создание нового),
   фильтр по тегу в истории и статистике, управление тегами в настройках.
   - Files: `web/js/views/add.js`, `web/js/views/history.js`,
     `web/js/views/stats.js`, `web/js/views/settings.js`, `web/js/store.js`.
   - Verification: ручная проверка создания тега, привязки, фильтрации.

## Verification Strategy

- Тесты: создание/удаление тегов, привязка к ставке, фильтрация списка и
  статистики по тегу, каскадное удаление тегов при удалении ставки.
- Ручная проверка: теги отображаются в карточке ставки, фильтр работает,
  статистика по тегу корректна.

## Критические риски

| Риск | Важность | Снижение риска |
|---|---|---|
| Изменение схемы БД у существующих пользователей | Высокая | `create_all` создаст новые таблицы, старые не трогает; теги опциональны |
| Дублирование тегов с разным регистром | Средняя | Нормализация имени тега при создании (`strip`, `lower`) |
| Производительность при многих тегах | Низкая | Индексы на `bet_tags(bet_id, tag_id)` |

## Out of Scope

- Цвета и иконки тегов (можно добавить позже).
- Иерархические теги (категории/подкатегории).
- Умные предложения тегов на основе истории.
