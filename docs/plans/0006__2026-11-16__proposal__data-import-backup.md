## Рассмотренные подходы

### Выбранный: импорт CSV с предварительной проверкой и бэкап через дамп

Импорт разбирает CSV в формате экспорта, валидирует строки и по флагу
`dry_run` возвращает отчёт без записи. Бэкап — выгрузка файла SQLite либо
JSON-дампа; восстановление — полная замена данных.

- Плюсы: совместимо с уже выгружаемыми файлами, безопасно за счёт `dry_run`.
- Минусы: нужно определить правила сопоставления полей и дублей.

### Отклонённый: XLSX как основной формат

Сделать импорт/экспорт только в XLSX. Отклонён: тянет обязательную зависимость
(`openpyxl`) и неудобен для скриптов и curl.

### Отклонённый: двусторонняя синхронизация с внешней таблицей

Постоянный обмен с Google Sheets. Отклонён: сетевые зависимости и конфликты
слияния не оправданы для локального приложения.

## Implementation Tasks

1. **Импорт ставок из CSV** — `POST /api/bets/import` (multipart, флаг
   `dry_run`), разбор колонок формата экспорта: дата, тип, вид спорта,
   событие, прогноз, коэффициент, сумма, источник, статус, комментарий.
   Источник сопоставляется по имени (создаётся при отсутствии).
   - Files: `app/imports.py` (или расширение `app/export.py`),
     `app/api/bets.py`, `app/services/bets_service.py`.
   - Verification: тест импорта файла, выгруженного через `/api/bets/export`;
     тест `dry_run` не пишет в БД; тест на некорректной строке.

2. **Экспорт XLSX (опционально)** — многолистовая книга («История», «Сводка»,
   «По видам спорта», «По источникам») только при наличии `openpyxl`
   (`importlib.util.find_spec`).
   - Files: `app/export.py`, `app/api/stats.py`.
   - Verification: тест пропускает XLSX-проверку при отсутствии зависимости.

3. **PDF-отчёт за период** — печатный отчёт со сводкой и разбивками.
   - Files: `app/export.py` (или `app/reports.py`), `app/api/stats.py`.
   - Verification: ручная проверка открытия PDF.

4. **Бэкап и восстановление** — `GET /api/system/backup` (файл БД или JSON-dump
   ставок/источников/настроек/операций) и `POST /api/system/restore`.
   - Files: `app/api/system.py`, `app/services/` (сервис дампа).
   - Verification: тест «создать данные → дамп → очистить → восстановить →
     данные совпадают».

5. **UI в настройках** — блок «Данные»: импорт CSV (с предпросмотром),
   скачивание бэкапа, восстановление, ссылки на XLSX/PDF.
   - Files: `web/js/views/settings.js`, `web/js/api.js`, `web/index.html`.
   - Verification: ручная проверка импорта и восстановления.

## Verification Strategy

- Тесты: round-trip «экспорт → импорт» не теряет и не дублирует ставки;
  `dry_run` безопасен; восстановление возвращает исходный набор.
- Полный `python -m pytest tests -q`.
- Ручная проверка: импорт файла из Excel и открытие XLSX/PDF.

## Критические риски

| Риск | Важность | Снижение риска |
|---|---|---|
| Потеря данных при восстановлении | Высокая | Автобэкап текущей БД перед заменой; подтверждение в UI |
| Дубли при повторном импорте | Средняя | Отчёт о дублях в `dry_run`; опция «пропускать совпадения» |
| Кривые строки ломают импорт | Средняя | Построчная валидация с указанием номера строки |
| XLSX/PDF тянут зависимости | Низкая | Формат опционален, проверяется `find_spec` |
