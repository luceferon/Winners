# Аналитика и отчёты: просадка, серии, сравнение периодов

## Workflow State

- Status: Completed
- Current Phase: 4 (Done)
- Package Manager: Not applicable (vanilla JavaScript frontend; no package manifest or lockfile)
- Framework: Vanilla JavaScript, no frontend framework
- Verification: `python -m pytest tests -q` (108 passed); browser smoke test of streaks, months report, period comparison and drawdown chart
- Цель: углубить аналитику без изменения модели данных — показать качество
  стратегии (просадка, серии), динамику по месяцам и сравнение периодов,
  а также позволить ранжировать источники по ROI, а не только по проходимости.

## Мотивация

Сейчас сводка отвечает на вопрос «сколько заработано», но не на вопросы
«насколько рискованна стратегия» и «становится ли лучше». Проходимость и
средний коэффициент не показывают просадку капитала и затяжные серии
поражений, а источники нельзя сравнить по доходности. Всё это вычисляется из
уже имеющихся данных — новых таблиц и полей не требуется.

## Рассмотренные подходы

### Выбранный: расширить `statistics_service.summary` и добавить endpoint сравнения

Просадку, серии и разбивку по месяцам считать в существующем агрегаторе
(`summary`) на основе `timeline` и списка решённых ставок; сравнение периодов
вынести в отдельный эндпоинт, который дважды вызывает `summary` и возвращает
дельты.

- Плюсы: переиспользует существующие запросы и графики, нет изменений схемы.
- Минусы: расширяет и без того крупный ответ `summary`.

### Отклонённый: отдельный сервис аналитики с материализацией метрик

Хранить вычисленные метрики в БД и обновлять фоновым пересчётом. Отклонён:
противоречит принципу «источник истины — ставки», усложняет инвалидацию.

### Отклонённый: расчёт полностью на фронтенде

Считать просадку и серии из загруженного `timeline` в JS. Отклонён: часть
данных (решённые ставки для серий) не попадает в ответ сводки, пришлось бы
грузить всю историю на клиент.

## Implementation Tasks

1. **Просадка и накопительный ROI** — добавить в `summary` ряд `drawdown`
   (накопительный оборот/профит и величина просадки от пика) и метрики
   `max_drawdown`, `current_drawdown`, `cumulative_roi_percent`.
   - Files: `app/services/statistics_service.py`.
   - Verification: тест на заранее заданной последовательности ставок с
     известной максимальной просадкой.

2. **Серии** — метрики `max_win_streak`, `max_lose_streak`, `current_streak`
   (по решённым ставкам в хронологическом порядке).
   - Files: `app/services/statistics_service.py`.
   - Verification: тест на последовательности `won/lost/won/won`.

3. **Разбивка по месяцам** — добавить `by_month` (ставок, оборот, профит, ROI,
   проходимость) и таблицу «Отчёт по месяцам» в интерфейс.
   - Files: `app/services/statistics_service.py`, `web/js/views/stats.js`.
   - Verification: тест на распределении ставок по двум месяцам.

4. **Сравнение периодов** — `GET /api/stats/compare` (`preset`/`date_from`/
   `date_to` и предыдущий период) → дельты по ключевым метрикам.
   - Files: `app/api/stats.py`, `app/services/statistics_service.py`.
   - Verification: тест на дельте между двумя непересекающимися периодами.

5. **Ранжирование источников** — параметры `sort` (`reliability`/`roi`/
   `bets_count`) и `order` в `GET /api/sources`; сортировка таблицы в UI.
   - Files: `app/api/sources.py`, `web/js/views/settings.js`,
     `web/js/views/stats.js`.
   - Verification: тест сортировки списка источников по ROI.

6. **Визуализация** — новые панели/таблицы: график просадки, карточки серий,
   таблица по месяцам, блок сравнения периодов.
   - Files: `web/js/charts.js`, `web/js/views/stats.js`, `web/index.html`.
   - Verification: ручная проверка на демо-данных.

## Verification Strategy

- Тесты бэкенда: просадка, серии, разбивка по месяцам и сравнение периодов на
  детерминированных наборах ставок; сортировка источников.
- Полный `python -m pytest tests -q`.
- Ручная проверка новых графиков и таблиц на демо-данных и на пустой базе.

## Критические риски

| Риск | Важность | Снижение риска |
|---|---|---|
| Неоднозначное определение просадки | Средняя | Зафиксировать формулу в тестах и в подписи графика |
| Рост размера ответа `summary` | Низкая | Новые ряды компактны; при необходимости — отдельный эндпоинт |
| Ставки с `push`/`cancelled` искажают серии | Средняя | В сериях учитывать только `won`/`lost` |
