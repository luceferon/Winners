## Мотивация

Сейчас данные существуют только внутри приложения. Пользователь не может
перенести их в Excel/Google Sheets для собственных расчётов, отправить
бухгалтеру или сделать резервную копию в читаемом формате. Экспорт — частый
запрос для приложений учёта финансов.

## Рассмотренные подходы

### Выбранный: экспорт через API + генерация файла на бэкенде

Добавить эндпоинты, возвращающие CSV (и опционально XLSX) по тем же фильтрам,
что и список ставок / сводка статистики. Файл формируется на сервере и
отдаётся с заголовком `Content-Disposition: attachment`.

- Плюсы: работает для любого объёма данных, один источник истины, можно
  использовать без UI (через curl).
- Минусы: для XLSX нужна зависимость (`openpyxl` или `xlsxwriter`).

### Отклонённый: генерация CSV на фронтенде

Собирать данные из уже загруженной таблицы и скачивать Blob. Отклонён:
фронтенд видит только текущую страницу пагинации; для полного экспорта
пришлось бы грузить все данные, что тяжело для больших баз.

### Отклонённый: только копирование в буфер обмена

Кнопка «Скопировать как CSV». Отклонён: не заменяет скачивание файла,
неудобно для больших объёмов.

## Implementation Tasks

1. **CSV-экспорт истории ставок** — `GET /api/bets/export` с теми же
   параметрами фильтрации, что и `GET /api/bets`. Ответ `text/csv`.
   - Колонки: дата, вид спорта, событие, прогноз, коэффициент, сумма,
     источник, статус, выплата, прибыль, комментарий. Для экспрессов —
     отдельные строки по ногам или плоский формат со списком событий.
   - Files: `app/api/bets.py`, `app/services/bets_service.py` (метод
     `export_bets`), возможно `app/export.py` (CSV-сериализация).
   - Verification: тест на корректные заголовки и данные.

2. **CSV-экспорт статистики** — `GET /api/stats/export?preset=...` — выгрузка
   сводки (counts, amounts, winrate, average coefficient, ROI) и разбивок
   по видам спорта и источникам.
   - Files: `app/api/stats.py`, `app/services/statistics_service.py`.
   - Verification: тест на наличие ключевых метрик в CSV.

3. **Опционально: XLSX с несколькими листами** — если есть зависимость
   `openpyxl`, один файл с листами «История», «Сводка», «По видам спорта»,
   «По источникам». Защита флагом (если `openpyxl` не установлен — только CSV).
   - Files: `app/export.py` (фабрика форматов).
   - Verification: тест пропускает XLSX-проверку при отсутствии зависимости.

4. **UI-кнопки экспорта** — в разделах «История ставок» и «Общая статистика»
   кнопка «Экспорт CSV» (и «Excel», если доступно), передающая текущие
   фильтры и период.
   - Files: `web/js/views/history.js`, `web/js/views/stats.js`, `web/js/api.js`.
   - Verification: ручная проверка скачивания файла.

## Verification Strategy

- Тесты бэкенда: CSV содержит правильные заголовки, данные отфильтрованы по
  периоду/виду спорта/источнику, кодировка UTF-8 с BOM для Excel.
- Ручная проверка: файл открывается в Excel/Google Sheets без искажения
  кириллицы, числа и даты парсятся корректно.

## Критические риски

| Риск | Важность | Снижение риска |
|---|---|---|
| Кириллица в Excel отображается кракозябрами | Высокая | Добавить BOM (`\ufeff`) в начало CSV; указать `charset=utf-8` |
| Очень большой экспорт тормозит сервер | Средняя | Лимит по количеству строк (например, 10 000) или стриминг |
| Даты и числа не парсятся в Excel | Средняя | Локализованный формат даты (`DD.MM.YYYY`), числа с точкой |
| Зависимость для XLSX ломает сборку | Низкая | XLSX — опционально, проверка `importlib.util.find_spec` |
