## [2.2.0] — 2026-11-26

### Краткое резюме (TL;DR)
Запуск на Windows превращён в приложение системного трея: консоль скрывается, в трее появляется значок **Winners** с меню «Отобразить окно сервера» / «Открыть в браузере» / «Выход». Вместо консоли показывается окно «Winners — сервер» (адрес, кнопки, хвост журнала); его закрытие сворачивает окно в трей, а сервер продолжает работать. Также Telegram-бот научился отправлять уведомления в группу: кнопка «Определить группу» находит группу через `getUpdates`, проверяет права администратора и подставляет `chat_id`. Исправлен парсер экспресса при трёх строках на ногу (событие + счёт + прогноз). Добавлена экспериментальная функция: при создании ставки из скриншота в Telegram отправляется фото ставки с замазанной суммой (включается настройкой `telegram_send_screenshot`); при этом **вся информация о деньгах** (ставка, сумма, выплата, баланс, прибыль, валюта) замазывается на скриншоте, а из текста уведомлений сумма и выплата убраны. Замазание стало надёжнее: фолбэк покрывает нижнюю половину изображения, а также строка с суммой ловится по распознанному значению ставки. Уведомление о расчёте ставки теперь приходит **ответом** на сообщение о её создании. Счетчик тестов увеличен до 185.

### ⚠️ Breaking Changes (Критические изменения)
- Отсутствуют. Обычный консольный запуск uvicorn возвращается флагом `--no-tray` (а также вне Windows или при отсутствии `pystray`/`tkinter`).

Сервер поднимается в фоновом потоке (`ServerThread`, остановка через `server.should_exit`), консольное окно скрывается (`ShowWindow`/`SW_HIDE`), в трее создаётся значок `pystray.Icon` с меню «Отобразить окно сервера» (по умолчанию, двойной клик), «Открыть в браузере» и «Выход».
- **`run.py`**: окно «Winners — сервер» на `tkinter` — заголовок, адрес сервера, кнопки «Открыть в браузере» и «Свернуть в трей», прокручиваемый хвост журнала `data/winners.log` (обновляется раз в секунду). Закрытие окна (`WM_DELETE_WINDOW`) сворачивает его в трей.
- **`run.py`**: новый флаг `--no-tray` — принудительный обычный консольный запуск без значка.

Пункт «Выход» завершает процесс-сервер вместе с дочерними (`taskkill /T`).

- **`web/js/api.js`**: метод `api.detectTelegram()`.
- **Экспериментальная функция — скриншот ставки в Telegram** (`telegram_send_screenshot`): при распознавании ставки со скриншота картинка временно сохраняется на сервере (10 минут); при сохранении ставки **вся информация о деньгах** (ставка, сумма, возможная выплата, баланс, прибыль, символы и коды валют) замазывается на скриншоте по всей ширине строки и отправляется в Telegram методом `sendPhoto` **с текстом ставки в виде подписи (caption)** — то есть одним сообщением вместо двух. Из текстовых уведомлений (и о создании, и о расчёте ставки) сумма и выплата тоже убраны. Замазание надёжнее: фолбэк покрывает нижнюю половину изображения, а строка с суммой дополнительно ловится по распознанному значению ставки. Уведомление о расчёте приходит **ответом** на сообщение о создании ставки (в БД ставки сохраняется `telegram_message_id`). Код помечен как тестовый: для удаления достаточно убрать `app/services/screenshot_store.py`, вызовы в `app/api/bets.py` и поле `screenshot_token` в схемах.
  - **`app/services/screenshot_store.py`** (новый): потокобезопасное in-memory хранилище скриншотов с TTL 10 минут.
  - **`app/services/ocr_service.py`**: `parse_image_full()` возвращает результат вместе с распознанными строками и координатами; `blur_stake_region()` замазывает все строки с деньгами по всей ширине (а также следующую строку с цифрами, если метка и сумма разделены) через расширенный паттерн `_MONEY_RE`; дополнительно ловит строку с суммой по значению `stake_value`.

### 🐛 Исправления ошибок (Fixed)
- **`run.py`**: кириллица в журнале окна отображалась знаками вопроса — процесс `--reload` писал вывод в системной кодировке (cp1251), а окно читало файл как UTF-8. Теперь серверный процесс запускается с `PYTHONUTF8=1` и `PYTHONIOENCODING=utf-8`.
- **`app/services/logging_service.py`**: вывод в консоль переведён в UTF-8 (`configure_console_utf8()`: перенастройка `sys.stdout`/`sys.stderr` и кодовая страница консоли 65001), иначе кириллица в консоли заменялась знаками вопроса.
- **`run.py`**: из окна журнала теперь можно копировать текст — кнопка «Копировать», пункты контекстного меню «Копировать»/«Выделить всё» и `Ctrl+C`; обновление журнала стало дозаписью в конец, поэтому выделение не сбрасывается раз в секунду.
- **`app/services/ocr_service.py`**: парсер экспресса принимал строки парами подряд, поэтому при трёх строках на ногу (событие, счёт, прогноз) счёт попадал в поле прогноза, а события смещались. Теперь событие определяется по шаблону «команда - команда» (с заглавных букв), прогноз — следующая строка после события, а строки со счётом (`X:Y`) пропускаются. Это поддерживает ноги как из двух, так и из трёх строк.

### 🚀 Новая функциональность (Added)
- **`app/services/ocr_service.py`**: сервис распознавания ставки со скриншота. Чтение изображения из буфера обмена (`PIL.ImageGrab`), офлайн-OCR через `Windows.Media.Ocr` (языки `ru`, затем `en-US`), предобработка (апскейл ×3 для мелких изображений) и парсер текста в поля `event_name`, `prediction`, `coefficient`, `stake`. Для экспресса собирает события экспресса парами строк (событие + прогноз) и привязывает коэффициент каждой ноги **по вертикальной координате** строки прогноза (коэффициент выровнен по правому краю на одной высоте с прогнозом своей ноги, а порядок строк в тексте OCR не гарантирован); общий коэффициент — число на высоте строки суммы. Единственный ненайденный коэффициент события досчитывается как «общий ÷ произведение остальных».
- **`app/schemas.py`**: схема `BetRecognitionOut` с распознанными полями, признаком вида `kind`, списком событий `legs` и исходным текстом `raw_text`.
- **`POST /api/bets/recognize`** (`app/api/bets.py`): принимает загруженный файл (`multipart/form-data`) либо, если файл не передан, читает изображение из буфера обмена; возвращает распознанные поля. При отсутствии изображения или недоступности OCR — `400` с понятным сообщением.
- **`web/index.html`**: в панели «Добавить ставку» добавлена кнопка «Вставить ставку».
- **`web/js/views/add.js`**: чтение изображения из буфера браузера (`navigator.clipboard.read`), вызов распознавания и автозаполнение полей формы с пересчётом; для экспресса переключается вид ставки и наполняются строки событий.
- **`web/js/api.js`**: метод `api.recognizeBet(blob)` и вспомогательная функция загрузки `upload()` на `FormData`.

### 🐛 Исправления ошибок (Fixed)
- Сумма с десятичной точкой распознавалась как целое число («Ставка 200.00» → `20000`): если у найденной суммы нет десятичного разделителя, изображение распознаётся повторно с бинаризацией, которая точку сохраняет. Из повторного прохода берётся только сумма — остальной текст обычный проход читает точнее.
- Коэффициенты экспресса привязывались к событиям по порядку строк в тексте, из-за чего раскладывались неверно (порядок строк у OCR не гарантирован). Теперь коэффициент каждой ноги определяется по вертикальной координате строки прогноза, а общий коэффициент — по высоте строки суммы.
