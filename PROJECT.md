# Winners — статистика спортивных ставок

Одностраничное веб-приложение (SPA) для ведения и анализа статистики спортивных ставок. Бэкенд — Python/FastAPI + SQLite, фронтенд — нативный JavaScript (ES-модули) без сборки, графики — ECharts (локальный бандл).

Приложение работает в ручном режиме: пользователь сам добавляет ставки и отмечает их результаты. Автоматического парсинга внешних данных и симуляции матчей нет.

---

## 1. Назначение и цели

Приложение помогает вести учёт ставок и оценивать их эффективность. Разделено на пять логических разделов одного экрана:

| Раздел | Назначение |
|---|---|
| **Общая статистика** | Сводка: количество ставок, выигрышных/проигрышных, суммы по категориям, финансовый результат, процент проходимости, средний коэффициент, 9 графиков (включая просадку капитала), серии выигрышей/поражений, отчёт по месяцам, сравнение периодов, выбор периода, экспорт сводки в CSV; панели можно перетаскивать (порядок сохраняется) |
| **История ставок** | Полный список ставок (одиночных и экспрессов) с фильтрами (статус, дата, вид спорта, источник), поиском, сортировкой, пагинацией, экспортом в CSV и действиями (изменить результат, дублировать, удалить); чекбоксы и панель массовых операций; фильтры сохраняются между запусками |
| **Новая ставка** | Форма ручного ввода одиночной ставки или экспресса (несколько событий) с валидацией, автодополнением событий и калькулятором размера ставки (фиксированный %, Kelly); блок «Активные ставки» |
| **Баланс** | Учёт пополнений и выводов средств, расчёт текущего баланса с учётом прибыли и активных ставок; кривая баланса, Yield и ROI, прогресс к цели и лимиты |
| **Настройки** | CRUD источников ставок (с сортировкой), банкролл и лимиты (цель, stop-loss, максимальный размер ставки), уведомления (встроенные тосты и Telegram-бот), отображение (валюта, тема, период, ROI, компактные таблицы), демо-данные и сброс |

Ключевая особенность: **ставки вводятся и рассчитываются вручную**. Одиночная ставка получает результат `won`/`lost`/`push`/`cancelled`; выплата и прибыль считаются автоматически из коэффициента и суммы. У экспресса отмечается результат каждого события (ноги), а итог экспресса вычисляется автоматически (проигрыш одной ноги → экспресс проигран; возврат учитывается как коэффициент 1.00).

## 4. Архитектура и взаимодействие модулей

### Слои бэкенда

```
HTTP-запрос
   ↓
app/api/*.py        — тонкие роутеры: валидация входа (Pydantic), HTTP-коды, Depends(get_db)
   ↓
app/services/*.py   — бизнес-логика: работа с ORM, статистика, настройки, банкролл
   ↓
app/models.py       — ORM (SQLAlchemy 2.0, типизированные Mapped[]), SQLite
```

### Модель данных (`app/models.py`)

| Таблица | Ключевые поля | Назначение |
|---|---|---|
| `sources` | `name` (unique), `url`, `enabled`, `notes` | Источники ставок; надёжность API вычисляет по выигранным и проигранным ставкам |
| `bets` | `kind` (single/express), `sport`, `event_name`, `normalized_event_name`, `prediction`, `coefficient`, `stake`, `source_id`/`source_name`, `status`, `payout`, `comment`, `created_at`, `settled_at` | Ставки пользователя |
| `bet_legs` | `bet_id`, `event_name`, `prediction`, `coefficient`, `status` | События экспресса (ноги) |
| `cash_flows` | `kind` (deposit/withdrawal), `amount`, `occurred_at`, `note` | Операции по счёту: пополнения и выводы |
| `settings` | `key` (PK), `value` (JSON) | Пользовательские настройки (переопределяют `DEFAULT_SETTINGS`) |

Особенности моделей:

- `UTCDateTime` (`TypeDecorator`) нормализует время в UTC на входе и выходе, т.к. SQLite не хранит tzinfo. Бизнес-время всегда UTC, отображение — в таймзоне `TIMEZONE`.
- `Bet.profit` — вычисляемое свойство: `won → payout − stake`, `lost → −stake`, `push → 0`, иначе 0.
- `Bet.potential_payout` = `stake × coefficient`.
- `Bet.is_express` — ставка из нескольких событий (`kind == "express"`); итог экспресса и его коэффициент вычисляются из результатов ног.
- Денормализованные `source_name`, `normalized_event_name` нужны для поиска (SQLite `lower()` не сворачивает кириллицу, поэтому поиск идёт по нормализованной форме через `app/textutils.normalize_title`).

### Статусы (единый словарь в `app/defaults.py`)

- Ставки: `pending` (активная) → `won` / `lost` / `push` (возврат) / `cancelled`.
- `SETTLED_STATUSES = (won, lost, push, cancelled)`.

### Расчёт результатов

**Одиночная ставка** (`bets_service.set_result`):
- `won` → `payout = stake × coefficient`, `profit = payout − stake`.
- `lost` → `payout = 0`, `profit = −stake`.
- `push` → `payout = stake`, `profit = 0`.
- `cancelled` → `payout = 0`, `profit = 0` (сумма возвращается, на баланс не влияет).
- Опциональный параметр `payout` позволяет переопределить выплату вручную.

**Экспресс** (`bets_service.set_leg_result`):
- Каждое событие (нога) получает свой статус.
- Если хотя бы одна нога `lost` — экспресс `lost`, выплата 0.
- Если все ноги `won` — экспресс `won`, выплата = `stake × (произведение коэффициентов всех ног)`.
- Ноги со статусом `push` учитываются как коэффициент 1.00 (не уменьшают и не увеличивают итог).
- Экспресс остаётся `pending`, пока есть нерассчитанные ноги.
- Статус экспресса нельзя установить напрямую — только через результаты ног.

## 6. Запуск в локальном окружении

```powershell
# 1. Зависимости
cd d:\project\Winners
python -m pip install -r requirements.txt

# 2. Запуск (браузер откроется автоматически)
python run.py

# Альтернативы
python run.py --port 8803 --no-browser     # другой порт, без открытия браузера
python run.py --reload                     # автоперезапуск при изменениях кода
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Приложение будет доступно на `http://127.0.0.1:8000` (или указанном порту),
Swagger — на `/docs`. База и логи создаются автоматически в `data/`.

Первый запуск на пустой БД наполняется демонстрационными данными
(несколько источников, набор одиночных ставок и экспрессов с разными статусами,
операции по счёту). Отключается переменной `WINNERS_SEED_DEMO=0` или
удаляется кнопкой «Удалить все данные» в разделе «Настройки».


`tests/conftest.py` задаёт `WINNERS_DATA_DIR` (временный каталог) и `WINNERS_SEED_DEMO=0`
**до импорта модулей приложения**, поэтому тесты не трогают рабочую БД и работают на
изолированной SQLite-базе из `tmp_path`.

## 7. Рабочие процессы и сценарии

### Добавление одиночной ставки
1. Раздел «Новая ставка» → вид спорта (справочник), название события (≥3 символов), коэффициент (> 1.00), сумма (> 0), прогноз, дата, источник, комментарий.
2. Валидация на клиенте (подсветка полей) + Pydantic-схема на сервере.
3. Сохранение: `POST /api/bets`. Ставка создаётся со статусом `pending`.
4. Блок «Активные ставки» обновляется.

### Добавление экспресса
1. Переключить тип ставки на «Экспресс».
2. Добавить минимум два события: название, прогноз, коэффициент.
3. Указать общую сумму ставки.
4. Сохранение: коэффициент экспресса считается как произведение коэффициентов ног.

### Дублирование и массовые операции
- Кнопка «Дублировать» в строке истории создаёт активную копию ставки (`POST /api/bets/{id}/duplicate`); у экспресса ноги сбрасываются в `pending`.
- Чекбоксы в таблице и панель `#history-bulk` позволяют сменить статус или удалить выбранные ставки (`POST /api/bets/bulk`). При массовой смене статуса экспрессы пропускаются (их статус определяется ногами) — сервер возвращает их число в поле `skipped`.

### Автодополнение и калькулятор ставки
- Поле «Название события» подсказывает ранее введённые события (`GET /api/bets/suggest`); при выборе подставляются коэффициент, прогноз, вид спорта и источник из последней такой ставки.
- Калькулятор `#bet-sizing` считает рекомендуемую сумму от текущего банкролла:
  режим «Вручную», «Фиксированный % банкролла» и «Kelly» (по оценке вероятности и коэффициенту). Кнопка «Подставить в сумму» переносит результат в поле ставки; при превышении лимита `max_stake_percent` показывается предупреждение.

### Горячие клавиши
- `n` — перейти к разделу «Новая ставка» и сфокусировать поле события;
- `/` — перейти в «Историю ставок» и сфокусировать поиск;
- `Esc` — закрыть модальное окно/боковое меню.

### Аналитика: просадка, серии, месяцы и сравнение периодов
- Раздел «Общая статистика» показывает максимальную просадку капитала (график `#chart-drawdown`), серии выигрышей/поражений (`summary.streaks`), отчёт по месяцам (`summary.by_month`) и сравнение с предыдущим периодом (`GET /api/stats/compare`, дельты по ключевым метрикам).

### Перетаскивание панелей статистики
- Все панели статистики (9 графиков, 3 таблицы и сравнение периодов) объединены в единый контейнер `#stats-panels` и поддерживают drag-and-drop.
- Перетаскивание начинается только за заголовок панели (`dragstart` обрабатывается только если предыдущий `mousedown` произошёл на `.panel-head`; графики, таблицы и кнопки не активируют перетаскивание).
- Порядок панелей сохраняется в настройке `stats_panel_order` (массив `data-panel`) и восстанавливается при загрузке; после `dragend` вызывается `resizeAll()` для корректного отображения графиков.

### Установка результата
- **Одиночная ставка** — иконка «Изменить результат» в истории → выбор статуса (`won`/`lost`/`push`/`cancelled`), опционально своя выплата → `PATCH /api/bets/{id}/result`.
- **Экспресс** — иконка «Результаты событий» → отметить статус каждой ноги; итог экспресса вычисляется автоматически.

### Уведомления о расчётах
Фронтенд раз в 45 с опрашивает `/api/bets/settlements/feed` и показывает тост о рассчитанной ставке (если уведомления включены в настройках).

### Банкролл
- Раздел «Баланс»: добавление пополнений (`deposit`) и выводов (`withdrawal`).
- Баланс = `пополнения − выводы + прибыль рассчитанных ставок − сумма активных ставок`.
- Отменённые ставки не влияют на баланс (сумма возвращается).
- Кривая баланса строится по дням из операций и рассчитанных ставок; карточки показывают Yield (доходность на оборот) и ROI (доходность на средний банкролл), а панель «Цели и лимиты» — прогресс к цели, уровень stop-loss и максимальный размер ставки (настройки в разделе «Настройки»).

### Источники ставок
- CRUD в разделе «Настройки»: название, сайт, комментарий, активность.
- Надёжность источника вычисляется автоматически как доля выигрышей среди ставок со статусами `won` и `lost`. При отсутствии решённых ставок — `null` (в интерфейсе «—»).

## 8. Известные особенности и ограничения

1. **Однопользовательское локальное приложение**: нет аутентификации и разграничения доступа, API не защищён — не предназначено для публикации в интернет как есть.
2. **Ручной ввод и расчёт**: приложение не подключается к внешним источникам данных и не рассчитывает результаты автоматически. Ставки и их результаты вводятся пользователем вручную.
3. **SQLite и кириллица**: `lower()` в SQLite не сворачивает регистр кириллицы, поэтому поиск по названиям событий идёт по нормализованному полю (`Bet.normalized_event_name`). Нормализация убирает пунктуацию и приводит текст к нижнему регистру, поэтому поиск нечувствителен к дефисам/кавычкам.
4. **Схема БД без Alembic**: таблицы создаются через `create_all`, а лёгкая миграция при старте (`_rebuild_if_drifted` в `app/database.py`) пересоздаёт таблицу, если у неё появились или пропали колонки, сохраняя данные. Версионированных миграций нет.
5. **Legacy-колонки источников удалены**: поля `kind`, `provider_key`, `api_key`, `reliability` больше не хранятся в `sources`; миграция при старте очищает старые базы, сохраняя данные.
6. **Фронтенд без сборки**: код раздаётся как есть (`/static/...`), минификации нет; ECharts подключён локальным файлом, поэтому интернет для интерфейса не нужен.
7. **Автотесты не покрывают браузерный слой**: pytest проверяет бэкенд и REST-контракты (клиент FastAPI); UI проверялся вручную.
8. **Длинные периоды в графике динамики**: если диапазон превышает 400 дней, пропускаются дни без ставок (иначе график становится нечитаемым).
